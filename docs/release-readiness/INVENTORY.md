# DNSid SDK Data & Network Inventory

Covers `dnsid-go`, `dnsid-ts`, `dnsid-py`. Answers InfoSec **COM-003**, **DAT-002**, **DAT-006**, **DAT-009**,
**IDT-005** and Legal §5 rows 1–3, 5. Facts verified against source on the `release-readiness` branches;
the host list is enforced by the allowlist in `ci/readiness.sh` ("network destinations" check).

Scope reminder: these are libraries. Nothing runs unless the integrator calls it; nothing is sent
anywhere the integrator (or the domain being verified) did not designate. No telemetry, usage
reporting, update checks, or crash reporting exist in any SDK.

## Network destinations

Not a destination: `witness.dnsid.ai` / `witness.dnsid.dev` appear in source only as witness *key names* inside
the bundled tlog policy. Witness cosignatures are delivered inside the log's checkpoint and verified offline; no
SDK ever opens a connection to a witness.

| Host | Trigger | Default or opt-in | Data sent | Data received | SDKs |
|---|---|---|---|---|---|
| System DNS resolver | `verify(domain)` | Default — resolver is the OS/configured one; **no hardcoded public resolver** | TXT query for `_dnsid.<domain>` | TXT record: key URL, status URL, entity key URL, log ref, profile | go, ts, py |
| JWKS URL from the TXT record (`ku`, `ek`) | `verify(domain)` | Default — host chosen by the domain owner | HTTPS GET, no body, no auth | Public keys | go, ts, py |
| Status URL from the TXT record | `verify(domain)` | Default — host chosen by the domain owner | HTTPS GET, no body, no auth | Agent lifecycle state (active / suspended / revoked …) | go, ts, py |
| `api.dnsid.ai` / `api.dnsid.dev` | Registry client (issuance, rotation, publication) | **Opt-in** — `DEFAULT_REGISTRY_URL` in ts/py registry packages; go has no default and requires the URL. Only reached from control-plane calls, never from `verify` | Signed publication requests: domain, public keys, governance ID | Status, receipts | ts, py (go: caller-supplied URL only) |
| `log.dnsid.ai` / `log.dnsid.dev` | C2SP transparency-log read/write | **Opt-in** — only when a `c2sptlog` log registry is configured. Public trust roots for these logs are bundled in source | Log entries (public keys, domain, event type); checkpoint reads | Checkpoints (with embedded witness cosignatures), inclusion proofs | go, ts, py |
| OIDC issuer / `token_endpoint` (integrator-supplied) | OIDC token exchange helper | **Opt-in** — integrator passes the issuer | Signed client assertion (DNSid JWT) | Access token | go, ts, py |
| AWS KMS (`kms.<region>.amazonaws.com`) | Signing with `key/aws` (go), `@dnsid-ai/key-aws` (ts), `AwsKmsKeyProvider` (py) | **Opt-in** — only if that provider is constructed | Digest to sign; AWS credentials from the integrator's environment | Signature | go, ts, py |
| GCP Cloud KMS | Signing with `@dnsid-ai/key-gcp` | **Opt-in** | Digest to sign; GCP credentials from the integrator's environment | Signature | ts |

Every default that reaches the network can be changed or disabled: resolver, HTTP transport, proxy, TLS options,
timeouts, and registry/log URLs are all injectable (`OPERATIONS.md` in go, `docs/security.md` in ts/py).
TLS certificate verification cannot be disabled through any SDK option (enforced: `readiness.sh` "TLS verification never disabled").

## Data inventory

"Personal data" here is limited to domain names and the public keys/URLs their owners publish; the SDKs hold
no user identifiers, IP logs, device IDs, or account data. IP addresses are visible only to the remote hosts
above in the ordinary course of DNS/HTTPS, exactly as for any client.

| Data | Collected / generated | Transmitted | Stored | Logged |
|---|---|---|---|---|
| Domain names verified | Supplied by integrator | To resolver, JWKS host, status host | In-memory verified-domain cache (below) | No |
| Counterparty public keys, status, evidence expiry | Fetched | No | In-memory cache | No |
| **Agent / entity private keys** (local key provider) | Generated on demand | **Never** — only signatures leave the process. KMS providers never see the private key at all | **`~/.dnsid/<domain>/keys.json`** (or `DNSID_CONFIG_DIR`), see below | No |
| Identity config (`domain`, `governance_id`, status/JWKS/entity/capabilities URLs, `log_ref`, `publish_profile`, `max_key_age`) | Generated by the CLI, read by the SDK | URLs are used as fetch targets; fields are included in signed publication requests when the registry client is used | `~/.dnsid/config.json`, `~/.dnsid/<domain>/config.json` | No |
| Transparency-log checkpoints (trusted tree size + root) | Fetched | No | In-memory by default; `TrustedC2spCheckpointStore` interface for integrator persistence | No |
| Signed JWTs, HTTP signatures, OIDC assertions | Generated per call | To the counterparty the integrator addresses | No | No |
| Cloud credentials (AWS/GCP) | Not handled — read by the cloud SDK from the environment | To the cloud KMS endpoint | No | No |
| Telemetry, usage, errors | **None** | **None** | **None** | **None** |

**Logging.** None of the three SDKs emit logs. go and ts return/throw errors; py declares a `logging`
logger under `dnsid` but never writes to it. Error messages carry domain names and key thumbprints, never
key material or tokens (DAT-004).

## Local files: `~/.dnsid`

| Property | Value |
|---|---|
| Location | `$DNSID_CONFIG_DIR`, else `~/.dnsid`. Layout: `config.json` (current-identity pointer) + `<domain>/{config.json,keys.json[,entity key]}` |
| Writer | The DNSid CLI (out of scope here) and the SDK local key provider on generation/rotation |
| Permissions | Files created `0600`, `O_EXCL`, written atomically via temp file + rename (go `keyprovider.go`, ts `local-key-provider.ts`, py `local_key_provider.py`) |
| Format | Plaintext JSON (JWK private keys) |
| Encryption at rest | **None. No passphrase option.** Protection is file mode + OS user boundary only |
| Production alternative | AWS KMS (go, ts, py) / GCP KMS (ts) providers: private key never leaves the HSM |

**Finding (DAT-006 / IDT-005):** local keys are stored unencrypted. Recorded as human decision #12 in
`STATUS.md` — proposed position: accept, document the local provider as development/single-host use,
recommend KMS providers for production. Same posture as `ssh-keygen` without a passphrase, `gcloud`, `aws`
CLI credential files.

## In-memory caches

| Cache | Contents | Lifetime | Persistence |
|---|---|---|---|
| Verified-domain cache (`IdentityCache`, `_InMemoryCache`) | `VerifiedDomain`: domain, keys, status, evidence expiry | Until evidence expiry or process exit; bounded capacity | Interface is pluggable; if an integrator persists it, that store and its retention are theirs |
| tlog checkpoint store | Latest trusted checkpoint per log | Process lifetime | Same — memory default, interface for persistence |

Retention (DAT-005): nothing is retained by the SDKs beyond process lifetime except the `~/.dnsid` files the
integrator explicitly creates. No deletion process is needed on the SDK side.
