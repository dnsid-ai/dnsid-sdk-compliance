## Findings

- **Partial — profile configuration ownership:** HTTP retains caller config (`packages/http-signatures/src/index.ts:279`); OIDC shallow-freezes mutable issuer/algorithm arrays (`packages/oidc/src/index.ts:470`). WBA's nested snapshot is separate.
- **Partial — cross-provider completion:** built-in local and AWS providers reject superseding the source's active key (`packages/sdk/src/local-key-provider.ts:179`, `packages/key-aws/src/index.ts:330`). The coordinator requires this after transfer (`packages/sdk/src/managed-key-rotation.ts:319`); capable injected providers work, but the built-in local-to-KMS path cannot finish.
- **Partial — empty rotation target:** reconciliation unconditionally calls `target.signingKey()` before `activate(newKid)` (`packages/sdk/src/managed-key-rotation.ts:313`). A focused assertion with the native test fixtures reproduced an accepted append followed by `ManagedKeyRotationActivationError` and zero activation calls for a target with no active key. Generation support validation alone does not cover this state.
- **Partial — managed trust transport:** the loader's managed branch omits effective transport (`packages/sdk/src/config-loading.ts:398`); the generic branch supplies it.
- **Partial — conformance metadata:** declarations now describe provider limitations (`packages/sdk/src/conformance.ts:34`), but omit profile ownership, empty-target activation, and managed transport. Onboarding and upfront configuration-validation findings are resolved.
- **Provider recovery constraint:** AWS and CLI/in-memory key state still needs caller-owned persistence; a provider resolver must reopen the saved state, not create a provider from changed deployment settings (`packages/sdk/src/conformance.ts:36`).

Focused validation: `node /tmp/dnsid-review-2026-10-20/check-empty-target.mjs`
reused the native rotation fixtures and confirmed the empty-target failure.

### Deployment Caveats

- **Managed trust cutover:** development and production pins were replaced without overlap (`packages/log-c2sp-tlog/src/managed-verification-registry.ts:13`, `:22`, `:44`). Persisted production checkpoint state may reject the replacement tree as rollback; re-baselining must be explicit and audited, never automatic.
- **Publication helper:** `verifyPublicationEvidence` is absent from published typings but remains callable from JavaScript (`packages/protocol/src/identity-manager.ts:612`). It requires local identity configuration and rejects counterparty domains; it is not an acceptance bypass.
- **Registry default:** the loopback `dnsid local` URL is design-permitted (`packages/registry/src/index.ts:120`); environment loading is explicit and credentials stay separate (`packages/sdk/src/config-loading.ts:488`).
- **DNS reuse:** default Node DNS captures wire TTLs; native fallback and missing/invalid TTLs use zero. Scoped/split DNS may require an explicit or injected resolver (`packages/transport/src/index.ts:212`, `:245`, `:612`; `packages/transport/src/txt-wire.ts:10`). Status freshness remains independent.
