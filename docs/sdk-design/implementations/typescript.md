and design `e2e76f9`..`e2f43a0`. Both recorded full commits resolve and
are ancestors of the reviewed heads. All four worktrees were clean at review
start. Inspected every intervening commit's subject and name/status changes,
then aggregate design/fixture and whole-SDK diffs, including releases,
dependencies, generated references, examples, packaging, and CI. No numbered
identity-record profile changed. The WBA draft target is published WG revision 00.

and content handling, profile configuration ownership, core refresh/cache/
freshness and DNS errors, managed log catalogs, checkpoint continuity/storage,
and loader injection before reviewing implementation. Fully reviewed the new
WBA verifier and revised checkpoint security boundaries, and followed their
core, transport, key-provider, error, and cache consumers. Other rows retain
their prior review after checking both change sets for impact. Citations in
changed SDK files are refreshed. Existing provider/registration gaps remain
unless explicitly revised below; a passing corpus does not close them.

## Findings

- **Partial — missing-record taxonomy:** empty answers are permanent `DNSResolution`, not the required `RecordNotFound` (`packages/protocol/src/identity-manager.ts:815`, `packages/protocol/src/errors.ts:2`). Built-in resolvers already normalize NXDOMAIN/NODATA; core absence code and complete transport-matrix tests remain open.
- **Partial — profile configuration ownership:** HTTP stores the caller configuration directly (`packages/http-signatures/src/index.ts:279`); OIDC's shallow freeze retains mutable issuer/algorithm arrays (`packages/oidc/src/index.ts:470`). Node assertions reproduced mutation of existing HTTP max-age and OIDC issuer policy. WBA's nested snapshot is separate and passes.
- **Partial — conformance metadata:** empty `knownDeviations` does not declare the construction-ordering, onboarding or cross-provider recovery gaps (`packages/sdk/src/conformance.ts:34`). The newly reviewed missing-record and profile-ownership gaps are also absent; metadata vectors validate declarations, not their completeness.
- **Partial — cross-provider rotation/recovery:** managed rotation still accepts one provider and saves no provider references; current signed publication/continuity and saved-signer restoration are not checked (`packages/sdk/src/managed-key-rotation.ts:33`, `:47`, `:63`, `:195`).
- **Partial — onboarding bindings:** typed authenticated reads do not validate/compare organization/GI/readiness bindings (`packages/registry/src/index.ts:579`).
- **Partial — provider validation ordering:** selected-provider availability/settings checks occur after log-policy work (`packages/sdk/src/config-loading.ts:350`, `:355`, `:398`). No mutation occurs, but design 12 recommends configuration errors before policy fetch.
- **Partial — construction ordering:** `constructIdentityManager` (`packages/sdk/src/config-loading.ts:348`) checks static config but may fetch `policyUrl` before `createNodeIdentityManager` rejects injected-transport conflicts (`packages/sdk/src/node-identity-manager.ts:35`), contrary to design 12's recommended ordering.

### Deployment Caveats

- **Managed trust cutover:** development and production pins were replaced without overlap (`packages/log-c2sp-tlog/src/managed-verification-registry.ts:13`, `:22`, `:44`). Persisted production checkpoint state may reject the replacement tree as rollback; re-baselining must be explicit and audited, never automatic.
- **Publication helper:** `verifyPublicationEvidence` is absent from published typings but remains callable from JavaScript (`packages/protocol/src/identity-manager.ts:612`). It requires local identity configuration and rejects counterparty domains; it is not an acceptance bypass.
- **Registry default:** the loopback `dnsid local` URL is design-permitted (`packages/registry/src/index.ts:120`); environment loading is explicit and credentials stay separate (`packages/sdk/src/config-loading.ts:471`).
- **DNS reuse:** default Node DNS captures wire TTLs; native fallback and missing/invalid TTLs use zero. Scoped/split DNS may require an explicit or injected resolver (`packages/transport/src/index.ts:212`, `:245`, `:609`; `packages/transport/src/txt-wire.ts:10`). Status freshness remains independent.
