## Findings

- **Resolved:** the consolidated `DnsidConfig`/`trustedEntities` contract is implemented; the former `Pre-redesign`/`TBD` rows are superseded by the configuration/acceptance section above.
- **Partial (open):** `IdentityManager.verifyPublicationEvidence` (`packages/core/src/identity-manager.ts:563`) is a public class method, present in the published type declarations, so the separate registry package can call it. It requires `config.identity` and rejects every domain except the local identity, so it cannot bypass acceptance for a counterparty, but it does return acceptance-free `VerifiedDomain` evidence for the local identity, which the design says public `VerifyDomain` must still gate. The design states this helper is not a new public API. Resolution options: move it behind a non-exported package boundary, or enable `stripInternal`/a symbol-keyed hook so it is not part of the published surface.
- **Resolved (0.19.1):** the acceptance test matrix now covers the unrelated delegated-agent case with verified bilateral binding and the Node transport-conflict tests observe that `dnsServer` reaches the default fetcher/resolver (`test/config-acceptance.test.ts:106`, `:116`, `:155`).
- **Behavior change to note:** the default Node DNS resolvers report TTL 0, disabling identity-evidence caching unless a TTL-aware resolver is injected. This is design-permitted (zero TTL means single use) but changes deployment performance characteristics relative to the earlier fixed 300-second TTL.
- **Validation scope:** `npm test`, typecheck, build, the 193-expectation shared harness, and the C2SP matrix all passed at the reviewed head; the constructor redesign is cross-cutting, so the shared suites were rerun rather than carried forward. The shared matrix covers ISSUANCE/KEY_ROTATION interoperability, not full recursive migration interoperability.
