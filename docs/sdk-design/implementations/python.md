## Findings

- **Partial — profile configuration ownership:** JOSE, HTTP and OIDC retain caller dataclasses (`dnsid/jose.py:113`, `dnsid/http_signatures.py:157`, `dnsid/oidc.py:261`). WBA copies/validates its own settings. This is now declared in conformance metadata.
- **Partial — JWT bearer naming:** `WebBotAuthProfile` still names JWT bearer authentication (`dnsid/web_bot_auth.py:117`), despite the contract reserving WBA for RFC 9421. Authorization-conflict rejection is implemented; the naming deviation is now declared.
- **Partial — managed log transport:** managed trust construction omits effective transport (`dnsid/config_loading.py:555`), unlike the generic branch (`:561`). Configured DNS, CA and private-host policy do not reach that managed fetcher through the loader.
- **Partial — OIDC decoded allocation:** token POST now streams and rejects an oversized decoded body during reads, fixing whole-response buffering. Both OIDC GET/POST still use `response.iter_bytes()` (`dnsid/oidc.py:870`, `:907`), so HTTPX decompresses each chunk before the size guard. A gzip probe produced a 2 MiB decoded chunk before the 1 MiB cap rejected it. Core/registry/C2SP raw readers instead use `BoundedBody` (`dnsid/_bounded_response.py:14`).
- **Partial — conformance metadata:** `known_deviations` now records ownership and naming (`dnsid/conformance.py:47`), but not managed transport, OIDC decoded allocation, or the issuance-recovery evidence limitation.
- **Partial — issuance-recovery evidence:** publication/signing primitives and registry prepare/submit transport still do not establish a durable end-to-end initial-issuance coordinator (`dnsid/manager.py:478`, `:492`, `:510`; `dnsid/registry_client.py:1322`). Restart/retry/acceptance/idempotent-completion evidence is still needed; this does not prove every supported composition lacks recovery.

### Deployment Caveats

- **Managed trust cutover:** development and production pins were replaced without overlap (`dnsid/c2sp_tlog/managed_verification_registry.py:23`, `:33`, `:79`). Persisted production checkpoint state may reject the replacement tree as rollback; re-baselining must be explicit and audited, never automatic.
- **Standalone migration verifier:** without a predecessor resolver it rejects migration genesis (`dnsid/c2sp_tlog/stream_bundle.py:354`, `:495`). Configured readers verify predecessor histories recursively (`tests/test_c2sp_migration.py:388`, `:436`); no new standalone resolver API is required solely to clear this limitation.
- **Package metadata:** release and editable lock versions now both record `0.31.0` (`pyproject.toml:7`, `uv.lock:509`); the runtime dnspython floor is `2.9.0` (`pyproject.toml:30`). Native validation refreshed the complete locked extras environment.
