## Findings

- **Partial — profile configuration ownership:** JOSE, HTTP and OIDC retain caller dataclasses (`dnsid/jose.py:113`, `dnsid/http_signatures.py:155`, `dnsid/oidc.py:261`). Focused assertions changed each existing profile's skew through the original configuration; WBA's copied/validated settings are not affected.
- **Partial — JWT bearer naming:** `WebBotAuthProfile` remains the public JWT bearer class (`dnsid/web_bot_auth.py:117`) despite design naming that reserves WBA for RFC 9421. Authorization-conflict rejection is implemented; a legacy-name disclaimer does not meet the public naming requirement.
- **Partial — configured signer binding:** construction opens the selected provider but does not verify its key against current signed publication (`dnsid/config_loading.py:484`, `:489`); the published-signing example checks this separately. Configuration-only signer replacement is not rejected by the factory.
- **Partial — construction ordering:** selected-provider availability/settings are checked after a possible log-policy fetch (`dnsid/config_loading.py:479`, `:484`, `:529`).
- **Partial — managed log transport:** the managed trust branch calls the factory without effective transport (`dnsid/config_loading.py:511`), unlike the generic branch (`:517`).
- **Partial — onboarding bindings:** the authenticated read returns raw account/proof data without validating/comparing expected bindings (`dnsid/registry_client.py:729`, `:755`).
- **Partial — missing DoH TTL:** `dnsid/_default_resolver.py:181` defaults to 300 seconds instead of zero when TTL is absent, contrary to design `a858525`. Native/shared passing results do not exercise this omission.
- **Partial — prepared-event metadata:** prepared events derive signed bytes locally but expose no required `eventId` field/property (`dnsid/c2sp_tlog/prepared.py:99`, `:342`).
- **Partial — OIDC response bounds:** token POST uses buffered `httpx.Client.post`; size is checked only after buffering (`dnsid/oidc.py:886`, `:938`). A bounded streamed POST is needed to enforce the limit during reads.
- **Partial — conformance metadata:** `known_deviations` is empty despite the prepared-event, OIDC response-bound, missing-DoH-TTL and new provider/account-binding gaps (`dnsid/conformance.py:47`). Profile-ownership gaps are also absent; metadata vectors validate declarations, not their completeness.
- **Partial — issuance-recovery evidence:** publication/signing primitives and registry transport do not substantiate durable end-to-end issuance/recovery (`dnsid/manager.py:432`, `:446`, `:464`; `dnsid/c2sp_tlog/prepared.py:119`). Identify and test the coordinator before claiming complete coverage; this is an evidence gap, not proof that every composition lacks recovery.

### Deployment Caveats

- **Managed trust cutover:** development and production pins were replaced without overlap (`dnsid/c2sp_tlog/managed_verification_registry.py:23`, `:33`, `:79`). Persisted production checkpoint state may reject the replacement tree as rollback; re-baselining must be explicit and audited, never automatic.
- **Standalone migration verifier:** without a predecessor resolver it rejects migration genesis (`dnsid/c2sp_tlog/stream_bundle.py:265`, `:398`). Configured readers verify predecessor histories recursively (`tests/test_c2sp_migration.py:388`, `:436`); no new standalone resolver API is required solely to clear this limitation.
- **Package metadata:** `uv.lock:288` records editable package `0.26.0`, while `pyproject.toml:7` reports `0.27.0`. The dnspython minimum is now 2.8 (`pyproject.toml:30`). Validation used existing installed environments without refreshing locks.
