Foundry Create/Active and recovery, open-only versus KMS-first creation boundaries,

## Findings

- **Partial — active-only provider inventory:** local/AWS list_key_ids still returns retained keys (`dnsid/local_key_provider.py:514`, `dnsid/aws_kms_key_provider.py:368`), unlike Google. This also defeats Foundry's KEY_MISSING check for a retained-only provider.
- **Partial — negotiated response bounds:** Signature-Input plus Signature use a 64 KiB combined limit rather than 16 KiB per field (`dnsid/http_signatures.py:1094`). Standalone response paths can accept an oversized individual field.
- **Partial — no-content response signing:** the signer hashes staged empty content but copies only headers back (`dnsid/http_signatures.py:518`, `:549`). A standalone HEAD/204/205/304 response can retain supplied bytes; ASGI middleware suppresses them.
- **Partial — profile configuration ownership:** JOSE, HTTP and OIDC retain caller dataclasses (`dnsid/jose.py:113`, `dnsid/http_signatures.py:161`, `dnsid/oidc.py:261`). WBA copies/validates its own settings. This remains declared in metadata.
- **Partial — JWT bearer naming:** WebBotAuthProfile still names JWT bearer authentication (`dnsid/web_bot_auth.py:117`). Authorization-conflict rejection is implemented; the naming deviation remains declared.
- **Partial — OIDC decoded allocation:** OIDC GET/POST uses response.iter_bytes, which decompresses before the guard (`dnsid/oidc.py:870`, `:907`). The earlier gzip probe is historical; these source paths are unchanged. Core/registry/C2SP instead use raw bounded decoding.
- **Partial — Google saved-state recovery:** inventory/eligibility are process-local (`dnsid/google_kms_key_provider.py:65`, `:73`). No built-in saved-pending/retained reopen path establishes the full managed crash-resume acceptance matrix. Reference-only open is a different contract.
- **Partial — Foundry successor reconciliation:** Active rejects a changed provider against saved currentPublicKey before public verification (`dnsid/foundry/_workflow.py:308`, `:744`). A verified successor cannot be adopted there unless saved state was updated externally.
- **Partial — Foundry release/hosted acceptance:** wheel/sdist exclude Foundry (`pyproject.toml:70`, `:74`). Native source tests do not establish a supported released server, permanent replay, shared hosted daily scenarios, external CLI or cross-binding recovery.
- **Partial — conformance metadata:** declared ownership/naming deviations (`dnsid/conformance.py:47`) omit the new boundaries and remaining OIDC/recovery gaps.

Resolved since the baseline: effective transport reaches managed log fetches
(`dnsid/config_loading.py:578`, `:586`), and durable initial issuance now supplies

### Deployment Caveats

- This is main at package version `0.34.0`, three commits after its release tag; published artifacts were not checked.
- Development bundle trust adds `62f7f9fa` alongside `0c241174` (`dnsid/c2sp_tlog/managed_verification_registry.py:23`). Earlier tree cutovers remain historical; incompatible persisted state needs explicit audited re-baselining.
