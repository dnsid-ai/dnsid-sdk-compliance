### Review and Validation Notes

The design delta adds opt-in negotiated response authentication, product-specific
Foundry Create/Active and recovery, open-only versus KMS-first creation boundaries,
active-only provider inventory, Google local supersession, protected registry
defaults and managed-log transport propagation. No identity-record profile or
wire selector changed. The full design range includes `conformance/` and root
`fixtures/`; root fixtures did not change. SDK changes also include security
guards, dependencies/runtime floors, package/release wiring, examples and API docs.

Shared commands ran from the compliance root after rebuilding `shims/go/dnsid-shim`:

```sh
.venv/bin/python harness/generate_c2sp_fixtures.py --check
.venv/bin/python harness/generate_wba_fixtures.py --check
.venv/bin/python -m unittest discover -s harness -p 'test_*.py'

.venv/bin/python harness/run.py --out /tmp/dnsid-review-2026-11-11/harness.md
.venv/bin/python harness/c2sp_matrix.py
```

The initial harness unit run failed because the shared Python environment imported
`dnsid-formal/results/diff/src/py`, not the reviewed checkout. With user approval,
`uv pip install -p .venv -e "$HOME/dnsid-py"` rebound it; the complete shared run then
passed against the three recorded SDK heads. Logs are in
`/tmp/dnsid-review-2026-11-11/`. Matrix writers matched canonical golden entries;
all three verifiers rejected all six mutations and the split-signing handoff matched.

Passing shared vectors do not establish complete response-verifier, provider,
Foundry, live-cloud or hosted-server coverage. Foundry native scenarios use local
fakes; no supported released server revision, hosted daily scenario matrix,
external CLI, cross-binding recovery-document transfer, destructive storage crash
test, external WBA partner, live IAM or load benchmark was validated. Checkpoint
durability remains caller-owned. Earlier focused probes mentioned below are
historical unless explicitly listed in this review's commands. No SDK fixes or
new regression tests were made.

## Findings

- **Partial — active-only provider inventory:** local/AWS ListKeyIds includes retained keys (`keyprovider.go:547`, `key/aws/awskms.go:361`), contrary to the revised contract. GetKeySet still selects only the active key. A retained-only provider also bypasses Foundry's empty-list KEY_MISSING branch.
- **Partial — negotiated no-content verification:** `responseContent` returns empty for HEAD/204/205/304 without checking supplied response bytes (`httpsig/response_signatures.go:326`). The verifier can accept a supplied nonempty no-content response instead of rejecting it. Shared vectors exercise signer/base behavior, not this boundary.
- **Partial — registry transport:** omitted and explicit-empty transport differ for local access (`registry.go:598`, `:627`); authenticated redirects can be followed (`:634`, `:1571`), and the 1 MiB read truncates without overflow detection (`:1579`). This conflicts with design 05's redirect and bounded-decoding requirements.
- **Partial — profile configuration ownership:** OIDC retains caller issuer/algorithm slices (`oidc/oidc.go:134`); profile constructors defer some invalid-config checks (`webbotauth/verification.go:55`, `webbotauth/webbotauth.go:435`). Earlier mutation probes were not rerun; the relevant ownership paths are unchanged.
- **Partial — publication snapshot role-host validation:** setup checks HTTPS syntax but not draft-01 ku/agent and ek/GI host constraints (`registration.go:42`, `identity_manager.go:124`, `:129`). The earlier bad-host probe is historical; public verification remains fail-closed.
- **Partial — rotation:** explicit algorithm selection/generated-algorithm agreement remain absent (`log/c2sptlog/managed_rotation.go:177`, `:181`, `:186`); state/options remain single-provider, without durable source/target references or application-signer restoration (`:20`, `:69`, `:83`). Same-provider publication, saved-key validation and terminal resume are implemented.
- **Partial — shared-kid prepared signing:** distinct role keys sharing a kid are accepted by readers but rejected during preparation (`log/c2sptlog/event.go:595`, `log/c2sptlog/prepared.go:487`). The prior focused probe was not rerun; these source paths are unchanged.
- **Partial — construction ordering:** injected-transport conflicts are checked after possible policy I/O (`config/config.go:392`, `:441`; `identity_manager.go:768`).
- **Partial — unavailable TTL:** absent wire capture returns an error rather than zero-TTL single-use evidence (`identity_manager.go:364`, `dns_ttl.go:37`). This fails closed but does not match the required behavior.
- **Partial — KMS recovery coverage:** Google inventory is process-local (`key/gcp/provider.go:39`) and AWS Load requires an active key (`key/aws/awskms.go:233`). Reference-only opening does not prove saved-pending/superseded restoration or the complete crash-resume acceptance matrix.
- **Partial — Foundry acceptance:** implementation is build-gated (`foundry/foundry.go:1`). Native tests do not establish permanent server replay, hosted daily scenarios, supported server revision, external CLI or portable cross-binding recovery.
- **Partial — conformance metadata:** KnownDeviations is empty (`conformance.go:29`) despite the gaps above.

Resolved since the baseline: configured operational signer binding
(`config/config.go:445`, `:456`) and setup-owned onboarding checks
(`foundry/foundry.go:390`). The revised design assigns established-identity
continuity to setup/recovery; ordinary construction alone is not continuity proof.

### Deployment Caveats

- Development bundle trust now adds key `62f7f9fa` alongside `0c241174` (`log/c2sptlog/managed_verification_registry.go:16`). The earlier production/development checkpoint cutover is historical; persisted incompatible trees still need explicit audited re-baselining, never an automatic reset.
- Foundry's local filesystem/race paths passed on macOS. Other platforms, destructive crashes and shared/container storage were not validated.
- Registry loopback HTTP remains a documented exception. Injected transports/providers must meet their own finite-timeout, cancellation and cleanup contracts.
- The earlier OIDC boundary test was revised to use deterministic timing (`oidc/boundaries_test.go:32`); uncached native and race suites passed. This is not a general load/stability claim.
