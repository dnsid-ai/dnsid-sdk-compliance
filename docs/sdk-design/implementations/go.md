## Review Scope — 2026-10-19

Incremental baseline comparison of SDK `3369ad9`..`1f6e49a`
and design `e2e76f9`..`e2f43a0`. Both recorded full commits resolve and
are ancestors of the reviewed heads. All four worktrees were clean at review
start. Inspected every intervening commit's subject and name/status changes,
then aggregate design/fixture and whole-SDK diffs, including releases,
dependencies, generated references, examples, packaging, and CI. No numbered
identity-record profile changed. The WBA draft target is published WG revision 00.

Mapped the changes to WBA signing/discovery/verification, shared HTTP signature
and content handling, profile configuration ownership, core refresh/cache/
freshness and DNS errors, managed log catalogs, checkpoint continuity/storage,
and loader injection before reviewing implementation. Fully reviewed the new
WBA verifier and revised checkpoint security boundaries, and followed their
core, transport, key-provider, error, and cache consumers. Other rows retain
their prior review after checking both change sets for impact. Citations in
changed SDK files are refreshed. Existing provider/registration gaps remain
unless explicitly revised below; a passing corpus does not close them.

## Findings

- **Partial — missing-record taxonomy:** design 01 now requires permanent `RecordNotFound`. Empty records still use `RecordInvalid`, and runtime not-found exceptions become transient `DNSResolution` (`identity_manager.go:349`, `:1103`, `:1109`, `errors.go:11`). DNSSEC checks already precede empty-answer classification.
- **Partial — profile configuration ownership:** OIDC retains caller issuer/algorithm slices (`oidc/oidc.go:134`), and profile constructors do not eagerly reject invalid configuration (`webbotauth/verification.go:55`, `webbotauth/webbotauth.go:435`). Focused assertions reproduced issuer-policy mutation and successful WBA construction with negative skew.
- **Partial — publication snapshot role-host validation:** creation validation delegates to `IdentityConfig.Validate`, which checks HTTPS syntax but not the draft-01 ku/agent and ek/GI host constraints (`registration.go:42`, `identity_manager.go:124`, `:129`). The prior review reproduced successful creation with `ku=https://other.test/ku` and `ek=https://unrelated.test/ek` for `agent.example.test` / GI `example.test`. Published-record verification remains separate and fail-closed; the setup snapshot should be rejected earlier.
- **Partial — configured signer binding:** `config.Construct` does not check configuration-selected keys against verified local publication (`config/config.go:377`, `:413`). Changing the source can replace the application signer without authorized rotation.
- **Partial — cross-provider rotation/recovery:** one-provider state/options lack saved provider references, current-publication verification, and signer restoration before unpause (`log/c2sptlog/managed_rotation.go:20`, `:67`, `:244`).
- **Partial — onboarding bindings:** `GetOrganizationOnboarding` decodes account/proof fields but does not validate or compare them (`registry.go:879`).
- **Historical validation issue — OIDC boundary test:** the prior review observed an intermittent exp=now float64 boundary failure (`oidc/boundaries_test.go:31`, `:34`). No OIDC source changed in this range. The current uncached full test and race runs both passed on their first attempt; this does not prove the earlier flake is fixed.
- **Partial — construction ordering:** `config.Construct` (`config/config.go:358`) defers injected-transport conflict checks until `NewIdentityManager` (`identity_manager.go:760`); a `policyUrl` can be fetched first.
- **Partial — unavailable TTL:** `identity_manager.go:357` errors when wire TTL capture is unavailable instead of returning zero for single-operation use, contrary to design `a858525`. Wire capture (`dns_ttl.go:37`) removes the former invented five-minute lifetime; this branch fails closed, not with stale success.
- **Partial — conformance metadata:** empty `KnownDeviations` (`conformance.go:29`) does not declare the unavailable-TTL, publication-snapshot or new provider/account-binding gaps. Passing metadata fixtures do not establish complete declarations. The newly reviewed missing-record and profile-ownership gaps are also absent; metadata vectors validate declarations, not their completeness.

### Deployment Caveats

- **Managed trust cutover:** development and production pins were replaced without overlap (`log/c2sptlog/managed_verification_registry.go:16`, `:25`, `:76`). Persisted production checkpoint state may reject the replacement tree as rollback; re-baselining must be explicit and audited, never automatic.
- **Registry default:** loopback HTTP is design-permitted (`registry.go:521`); environment loading is explicit (`config/config.go:487`).
- **Hosting:** injected dependencies must honor cancellation and HTTP hosts/custom body readers must impose read deadlines. The synchronous provider API cannot interrupt a blocked custom signer (`OPERATIONS.md:66`).
